# PRD：Dialogue Board（台词管理网页）

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.5 |
| 日期 | 2026-10-27 |
| 状态 | 已实现 |

## 1. 背景

本项目用于里昂（Leon S. Kennedy）与艾达（Ada Wong）的电影化对白润色，场景中也可能出现其他角色。台词数量多时，在聊天记录里查找、修改某一句很不方便。因此需要一个本地网页，按场景集中管理所有台词，并给每句台词一个唯一 ID，方便之后按 ID 定位、替换，也方便和 `re-dialogue-refiner` skill 的 `L###-V#` 编号对应。

## 2. 目标

- 按场景（scene）组织台词：先建场景，再在场景里写台词。
- 每个场景有独立的网址，可以直接打开、收藏、刷新。
- 快速录入新台词：先选说话人，再输入台词。
- 对任意一句台词、任意一个场景进行编辑或删除。
- 场景和台词都有稳定、不重复的 ID。
- 数据保存在本地 JSON 文件里，不需要数据库；重启后不丢失，Claude 也能直接读取。

### 非目标（当前版本不做）

- 多人协作、登录、云端同步、数据库。
- 台词拖拽排序、在中间插入；台词在场景之间移动。
- 每句台词的中英双语字段、三个版本（V1/V2/V3）的并排管理。
- 整个场景一次性润色（当前只支持逐句润色）。

## 3. 用户与场景

- **用户**：编剧本人，单人在本机使用。
- **场景 1**：打开首页，新建场景"村庄教堂"，点进去后逐句录入台词，得到 `L001`、`L002`……的编号。
- **场景 2**：在 Claude Code 里说"重写 L007"，拿到新台词后，进入对应场景，点铅笔图标进行编辑。
- **场景 3**：删掉不要的台词或整个场景，其余台词和场景的编号保持不变。

## 4. 页面与路由

| 网址 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页（场景列表） | 打开网页默认进入 |
| `/scene/:n` | 场景页 | `n` 为场景编号的数字部分，例如 `/scene/1` 对应 `S001` |
| `/styles` | 风格设置 | 编辑润色用的三个默认风格 |
| 其他 | 404 页 | 提示页面不存在，并提供返回首页的链接 |

所有页面顶部都有：标题（点击回到首页）、右上角"风格设置"入口和语言切换。

## 5. 功能需求

### 5.1 首页：场景列表

- 以卡片形式显示全部场景，每张卡片显示：**场景名**、**场景 ID**、**台词数量**、**铅笔图标**。
- 点击卡片进入该场景页（`/scene/n`）。
- "+ 新建场景"按钮：弹出"新建场景"窗口，输入场景名，可选填写**原剧本参考**（见 5.2），点"创建"确认；点"取消"、按 Esc 或点窗口外关闭。创建后留在首页，新场景出现在列表末尾。
- 铅笔图标菜单：
  - **重命名**：弹出"重命名场景"窗口，默认填好当前名字。场景 ID 不变。
  - **删除**：卡片内出现"删除这个场景和其中的 N 句台词？"确认。确认后场景和其下所有台词一起删除。
- 没有场景时显示提示："先新建一个场景，才能开始写台词"。

### 5.2 场景页：台词列表

- 顶部有"← 返回场景列表"链接，下方显示场景名、场景 ID 和台词数量。
- 场景名旁边有**齿轮图标**：打开"编辑场景"窗口，可修改场景名和**原剧本参考**（`source`）。
  - 原剧本参考是多行文字：可以粘贴这一段的原台词（建议一行一句"说话人: 台词"），也可以只填剧本网页链接。
  - 润色和 AI 预测时自动作为参考资料发给 LLM（粘贴的文字排在最前面，链接和额外要求里的链接一起读取，合计最多 3 个），不用每次在额外要求里贴链接。读取结果里显示为"原剧本参考"。
  - 打开"优先使用参考里的原台词"时，AI 预测会在原文里找到当前位置，直接按顺序取后面的台词。
- 按添加顺序显示该场景的台词，每行显示：**ID**、**说话人**、**中文台词**及其下方的**英文台词**（灰色小字；哪种语言为空就不显示）、行尾的**铅笔图标**。
- Leon、Ada 和其他角色的说话人名字用不同颜色区分。
- 场景没有台词时显示提示文案。
- 场景不存在（例如已删除或编号写错）时，显示"找不到这个场景"和返回链接。

### 5.3 新增台词（场景页底部输入区）

- 左边是**说话人下拉列表**，右边是**台词输入框**，最右边是"添加"按钮。
- 输入框只有一个，按内容自动判断语言：含中文字符存入 `cn`，否则存入 `en`；另一种语言可以通过润色或编辑补上。
- 下拉列表的选项：
  - **背景 / 旁白**分组（排在最前）：
    - **背景介绍**：剧情背景、场景说明，直接添加，**不走 LLM**（菜单里没有"润色"，后端也拒绝润色）。润色其他台词时作为上下文发给模型。列表中以灰色底显示。输入框提示会变成"输入背景介绍（不会润色）"。
    - **旁白**：电影化的画外音 / 叙述，可以润色，以斜体显示。
    - 数据里固定存为 `Background` / `Narrator`，界面按当前语言显示。
  - **人物**分组：登场人物名单里的所有人物（见 5.3.1）。下拉列表**只能选择，不能添加**人物；默认选中名单里的第一个人物。编辑台词时的下拉列表也一样。

#### 5.3.1 管理登场人物

- 场景页标题行最右边（`justify-content: flex-end`）有"管理登场人物"按钮，点击弹出窗口。
- **每个场景有自己的人物名单**，存在该场景的 `characters` 数组里，每个人物是 `{ name, notes }`。新建场景时名单为 Leon、Ada、Claire、Chris、Jill、Wesker、Sherry、Ashley、Luis、Hunnigan、Krauser。
- **人物设定（`notes`）**：可选的多行文字，可以手写性格特点、说话方式，也可以放台词参考链接（例如 Fandom 的 quotes 页面）。润色本场景任何一句台词时：
  - 场景里所有说过话的人物的设定都会作为"人物设定"发给 LLM，目标说话人排在最前；
  - 只有目标说话人设定里的链接会被抓取，和"额外要求"里的链接一起（额外要求优先，合计最多 3 个）；其他人物的链接只作为文字发送。
- 每个人物显示名字、本场景台词数量和人物设定（最多显示 3 行），可以：
  - **编辑**：修改名字和人物设定；改名时本场景台词的说话人同步改名；有"保存"和"取消"。
  - **删除**：在本场景没有台词的人物直接删除；有台词时先在该人物下方提示"删除此人物会同时删除这些台词"（显示台词数量），点"确定"后删除人物和本场景里他的所有台词，点"取消"或按 Esc 放弃。
- 底部表单添加新人物（名字 + 人物设定）。名字不能为空，不能和本场景已有人物重复（不区分大小写），也不能用保留名 `Background` / `Narrator`；出错时在窗口内提示。
- 点"关闭"、按 Esc 或点窗口外的区域关闭。

- "添加"按钮右边是 **LLM 下拉列表**，列出 `.env` 里配置的所有模型，用于选择润色时使用哪个模型：
  - 只配置了一个模型时，列表里只显示这一个；配置了多个服务时，选项显示为"服务 · 模型"。
  - 没有配置任何模型时，显示"未配置 LLM"，并且不可选。
  - 选择保存在浏览器里，下次打开时保持不变；如果之前选的模型已从 `.env` 删除，自动改用第一个。
- 按回车或点"添加"提交；说话人或台词为空时不能提交。
- 提交后清空输入框，保留当前选择的说话人，并把列表滚动到最新一句。
- 输入区固定在页面底部。

### 5.4 编辑 / 删除台词

- 点击铅笔图标，弹出菜单：**润色**（背景介绍没有）、**编辑**、**删除**。点击菜单以外的地方会关闭菜单。
- **编辑**：这一行变成编辑状态，可以修改说话人（同样是下拉列表）、中文和英文（至少填一种）。点"保存"或按回车保存，点"取消"或按 Esc 放弃修改。**ID 和所属场景保持不变。**
- **删除**：行内出现"删除这句？"的确认，点"删除"确认、点"取消"放弃。删除后这个 ID 不会再分配给新台词。

### 5.5 AI 润色

- 台词铅笔菜单里有"**润色**"（背景介绍除外）。旁白按电影旁白风格润色。
- 润色窗口分三步，**点"润色"菜单时不会立刻请求 LLM**：
  1. **确认风格**：显示本次使用的三个风格（默认来自"风格设置"），每个风格有名称和说明，可以针对本次临时修改（不影响默认风格）；每个风格卡片标题行左边是"版本 N"，右边是**开关**，关掉的风格整张卡片变灰、不能编辑，本次不生成（至少保留一个开启，只需要一个版本时关掉另外两个）；可填写"额外要求"。点"**润色**"后才发给 LLM。
  2. **选择版本**：显示三个版本，每个版本标注风格名，每个版本同时给出**中文**和**英文**（`cn` / `en`，意思和语气一致）。原句只有中文、只有英文或两者都有都可以。点"**选这个**"进入下一步；也可以"调整风格"回到第 1 步，或"重新生成"。
  3. **修改**：只显示选中的那一版，中文和英文都可以修改。下方询问"**需要再次润色，还是直接保存？**"
     - "**再次润色**"：把修改后的台词（加上额外要求、沿用已确认的风格）发给 LLM，回到第 2 步；
     - "**保存**"：把中文和英文一起保存到这句台词（ID 不变），关闭窗口；
     - "← 返回重新选择"：回到第 2 步换一个版本。
- 在保存之前，原句始终不变；中途关闭窗口不会修改任何数据。
- **额外要求**是多行输入框，可以写要求，也可以粘贴**参考链接**（例如角色以前台词的网页，最多 3 个）：
  - 后端自动抓取网页正文（优先取 `<main>` / `<article>`，每个最多 20000 字，可用 `.env` 的 `REFERENCE_MAX_CHARS` 调整，也可以按服务单独设置），作为说话风格的参考和要求一起发给 LLM；提示词注明这些内容只是参考资料，其中的指令一律忽略。
  - 生成后在版本列表上方显示每个链接的结果："✓ 已读取 N 字"或"✗ 读取失败（原因）"。读取失败不影响润色，只是不使用该参考。
  - Fandom 等 wiki 会拦截直接访问网页（403），此时自动改用该站的 MediaWiki 接口（`/api.php?action=parse`）读取同一页面，例如 `https://residentevil.fandom.com/wiki/Ada_Wong/quotes` 可以正常读取。其他拦截自动访问的网站，需要把参考内容直接复制到额外要求里。
  - 抓取结果在服务端缓存 10 分钟，"再次润色"时不会重复抓取。

#### 参考资料的读取规则（润色和 AI 预测共用）

- 每个参考链接最多发送 `REFERENCE_MAX_CHARS` 字（默认 20000）；当前模型所属服务设置了 `LLM_<NAME>_REFERENCE_MAX_CHARS` 时用它（Gemini 默认 300000，一整部剧本可以全文发送，由模型自己找到当前场景、学习人物说话方式）。页面更长时（例如整部游戏的剧本 transcript），**用场景里的台词在页面里找最匹配的一行**，截取它附近的一段（前面约 30%、后面约 70%）：
  - 润色：用目标句和它前后各一句匹配；
  - AI 预测：用最后 3 句匹配（最近一句优先），这样截取的部分包含"接下来"的原文。
  - 找不到匹配时，才退回只读取页面开头。
  - 找到匹配时（包括全文发送的情况），在发给模型的正文里插入"当前场景演到这里"的标记，模型不用自己在整部剧本里找位置。
- 读取结果会显示：已读取全文、"截取了与当前场景匹配的 N 字"，或"⚠ 没找到匹配段落，只读取了开头"。读取失败（例如网站拒绝自动访问，返回 403）显示红色提示，这时需要把网页文字复制进来。
- **"优先使用参考里的原台词"开关**（在"额外要求"下方）：打开后，如果参考资料里有同一段剧情，模型直接用原文台词作为英文，并翻译成中文；续写时按原文顺序往下接。AI 预测和润色各自记住上一次的选择（存在浏览器里，`dialogue-board.predict.preferOriginal` / `dialogue-board.refine.preferOriginal`）；第一次使用时 AI 预测默认打开，润色默认关闭。
  - AI 预测时，如果在参考剧本里找到了当前场景的位置，**直接按顺序取原文后面的台词**作为英文（不经过模型，结果固定），模型只把它们翻译成中文；后面的说话人不是本场景人物时就停下，所以可能少于要求的句数。找不到位置时才由模型续写。

### 5.5.1 风格设置（`/styles`）

- 页面顶部的"**风格设置**"进入，编辑三个版本的默认风格：每个风格有**风格名称**和**风格说明**（告诉 LLM 怎么写）。固定三个。
- 点"保存"后写入项目根目录的 `styles.json`。网页润色和对话里的 `re-dialogue-refiner` skill 都从这个文件读取风格，不再写死在代码或 skill 里。
- 默认值：Standard Cinematic（经典游戏/电影风）、Dynamic & Teasing（调侃拉扯风）、Raw & Gritty（地道美式硬朗风）。
- 使用底部 LLM 下拉列表当前选中的模型。
- 生成时会把**整个场景**的台词（目标前后都有）作为上下文一起发给模型，目标那句用 `>>>` 标出，让新台词和前后文衔接。
- 再次润色时，整段台词里那一句也替换成用户修改后的版本，模型不会同时看到新旧两个版本。不跨场景发送。
- 提示词直接读取 `re-dialogue-refiner` skill 的规则，保证网页和对话里的润色风格一致；修改 skill 后无需重启即可生效。
- 没有配置 LLM、模型服务连不上或返回格式不对时，窗口里显示错误信息，原句不受影响。

### 5.5.2 AI 预测后续台词

- 场景页台词列表最下面（列表末尾）有"✦ AI 预测"按钮；`.env` 没有配置 LLM 时按钮置灰并提示。
- 点击后弹出窗口，两步：
  1. **设置**：用下拉菜单选择预测几句（1～10 句，默认 3 句）；可填写"额外要求"（同润色，可以粘贴参考链接）。点"预测"后才发给 LLM，使用底部 LLM 下拉列表选中的模型。
  2. **结果**：显示预测出的台词（说话人 + 中文 + 英文），每句前面有勾选框，默认全选；取消勾选的变灰。可以"调整设置"回到第一步、"重新预测"、"关闭"，或"添加选中的 N 句"。
- 添加后按顺序追加到场景末尾，各自分配新的台词 ID；之后可以像普通台词一样编辑、润色、删除。预测结果不点"添加"就不会保存。
- 发给 LLM 的内容：整个场景的台词、本场景人物名单和设定、额外要求；说话人只能是本场景人物、旁白或背景（其他说话人的句子会被丢弃）。参考链接先取额外要求里的，再取场景里已出场人物设定中的（合计最多 3 个）。
- 提示词同样以 `re-dialogue-refiner` skill 为基础，并明确说明这次是用户要求续写，不受 skill 里"不主动续写剧情"的限制。

#### 预测日志

- 每次 AI 预测（成功或失败）都会在 `logs/predict.jsonl` 里追加一行记录，方便分析：时间、场景、模型、句数、是否优先原台词、额外要求、最后 3 句台词、每个参考资料的读取情况（是否找到当前场景、匹配位置后面约 600 字）、走的是"直接取原文"还是"模型续写"、模型原始输出、最终结果或错误、耗时。
- 只保留最近 100 条，超过时自动删除最早的记录。

### 5.6 界面语言

- 页面右上角有语言切换按钮：**中文 / EN**，默认中文。
- 切换后，所有界面文字（标题、按钮、提示、弹窗）立即变成对应语言；场景名、台词内容和角色名不翻译。
- 选择的语言保存在浏览器里，下次打开时保持不变。
- 文案统一放在 `client/src/translation/cn.js` 和 `en.js`。

### 5.7 ID 规则

- **场景**：`S` 加三位数字（`S001`、`S002`……）；网址里只用数字部分（`/scene/1`）。
- **台词**：`L` 加三位数字（`L001`、`L002`……），**全局唯一**，不按场景重新编号。
- 超过 999 后位数自动增加。
- 都由服务端按自增计数器分配，**永不复用**，删除场景或台词不影响计数。
- 台词编号和 `re-dialogue-refiner` skill 的 `L###` 格式一致；skill 输出的 `-V1/-V2/-V3` 是版本后缀，网页只存定稿的那一版。

## 6. 技术方案

| 层 | 选型 |
| --- | --- |
| 前端 | React 18 + Vite + React Router 7（`client/`） |
| 后端 | Node.js 原生 `http`，无额外依赖（`server.js` + `server/`） |
| LLM | 任意 OpenAI 兼容接口（`/chat/completions`），在 `.env` 里配置；可用免费在线服务（Gemini、Groq、OpenRouter 免费模型），之后换成本地 Ollama / LM Studio 只需改 `.env` |
| 存储 | 项目根目录下的 `dialogue.json`（先写临时文件再重命名，避免写坏） |
| 端口 | 默认 3000，可用环境变量 `PORT` 修改；只监听 127.0.0.1 |

没有扩展名的网址（如 `/scene/1`）由服务端统一返回 `index.html`，交给前端路由处理。

### 6.1 数据结构（`dialogue.json`）

```json
{
  "nextSceneNumber": 2,
  "nextLineNumber": 3,
  "scenes": [
    {
      "id": "S001",
      "name": "村庄教堂",
      "source": "Ada: ……
Leon: ……",
      "characters": [
        { "name": "Leon", "notes": "" },
        { "name": "Ada", "notes": "冷静、神秘 https://residentevil.fandom.com/wiki/Ada_Wong/quotes" }
      ]
    }
  ],
  "lines": [
    { "id": "L001", "sceneId": "S001", "speaker": "Leon", "cn": "……", "en": "..." },
    { "id": "L002", "sceneId": "S001", "speaker": "Ada", "cn": "……", "en": "" }
  ]
}
```

旧格式的数据文件在读取时会自动转换：
- 没有场景的旧文件：原有台词归入一个名为 "Scene 1" 的场景，台词编号保持不变。
- 场景没有 `characters` 的旧文件：用默认名单（或旧版顶层的 `characters` 名单）加上该场景里已经说过话的人物（背景、旁白除外）。
- 旧格式在读取时转换后会立即写回 `dialogue.json`。
- 台词是 `{ text, translation }` 的旧文件：`text` 含中文则存入 `cn`、`translation` 存入 `en`；否则反过来。

### 6.2 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/scenes` | 获取全部场景 |
| POST | `/api/scenes` | 新建场景，body：`{ name, source? }` |
| PUT | `/api/scenes/:id` | 修改场景名和原剧本参考，body：`{ name, source? }`（不带 `source` 时保留原来的），ID 不变 |
| DELETE | `/api/scenes/:id` | 删除场景及其全部台词 |
| GET | `/api/scenes/:id/characters` | 该场景的人物名单 `[{ name, notes }]`（`GET /api/scenes` 返回的场景里也带着） |
| POST | `/api/scenes/:id/characters` | 添加人物，body：`{ name, notes? }`；重名（不区分大小写）或保留名返回 400；返回新名单 |
| PUT | `/api/scenes/:id/characters/:name` | 修改，body：`{ name, notes? }`；改名时该场景台词的说话人同步修改；返回新名单 |
| DELETE | `/api/scenes/:id/characters/:name` | 删除人物，同时删除该人物在本场景的台词（前端先确认）；返回新名单 |
| GET | `/api/lines` | 获取全部台词（每句带 `sceneId`） |
| POST | `/api/lines` | 新增台词，body：`{ sceneId, speaker, cn, en }`（`cn` / `en` 至少一个），场景不存在时返回 400 |
| PUT | `/api/lines/:id` | 修改说话人和台词，ID 和所属场景不变 |
| DELETE | `/api/lines/:id` | 删除台词 |
| POST | `/api/lines/:id/refine` | 润色，body：`{ draft?, instruction?, styles?, llm?, preferOriginal? }`，返回 `{ versions: [{ cn, en }]（每个风格一个）, references: [{ url, ok, chars?, total?, mode?, error? }] }`，不会修改数据；`instruction` 里的链接会被抓取作为参考；`draft`（`{ cn, en }`）是再次润色时用户修改后的版本（不填则用已保存的原句）；`styles` 是本次开启的 1～3 个风格（不填则用 `styles.json` 的三个）；`llm` 不填时用第一个模型 |
| POST | `/api/scenes/:id/predict` | AI 预测，body：`{ count, instruction?, llm?, preferOriginal? }`（`count` 为 1～10），返回 `{ lines: [{ speaker, cn, en }], references }`，不会修改数据 |
| GET | `/api/styles` | 默认风格 `[{ name, description }] ×3` |
| PUT | `/api/styles` | 保存默认风格，body：`{ styles }`，必须正好 3 个且都有名称 |
| GET | `/api/llms` | 已配置的模型列表 `[{ id, provider, model }]`，不包含地址和 key |

必填字段为空或 `llm` 不存在时返回 400，ID 不存在时返回 404，LLM 未配置返回 503，LLM 调用失败或返回格式不对返回 502。

### 6.3 LLM 配置（`.env`）

可以同时配置多个服务，每个服务可以有多个模型，全部出现在 LLM 下拉列表里。

| 变量 | 说明 |
| --- | --- |
| `LLM_PROVIDERS` | 启用的服务名，用逗号分隔，例如 `gemini,ollama` |
| `LLM_<NAME>_BASE_URL` | 该服务的 OpenAI 兼容接口地址，例如 `http://localhost:11434/v1` |
| `LLM_<NAME>_API_KEY` | 该服务的 API key；本地模型可以不填 |
| `LLM_<NAME>_MODELS` | 该服务的模型名，用逗号分隔 |
| `LLM_<NAME>_REFERENCE_MAX_CHARS` | 可选，用这个服务的模型时每个参考链接最多发送的字数，覆盖 `REFERENCE_MAX_CHARS`；长上下文模型（如 Gemini）可以设大，让整部剧本全文发送 |
| `LLM_TIMEOUT_MS` | 超时时间，默认 120000 |
| `REFERENCE_MAX_CHARS` | 每个参考链接最多读取的字数，默认 20000；本地小模型上下文短时调小 |

模型 ID 为 `服务名/模型名`（例如 `gemini/gemini-3.5-flash`）。第一个服务的第一个模型是默认模型。`.env.example` 里列出了各家服务的填写示例。`.env` 已加入 `.gitignore`，修改后需要重启服务。

### 6.4 启动方式

- 首次使用：`npm.cmd install`
- 日常使用：`npm.cmd start`（先构建前端，再启动服务），然后打开 http://localhost:3000
- 开发时：一个终端运行 `npm.cmd run server`，另一个终端运行 `npm.cmd run dev`（热更新，`/api` 会转发到 3000 端口）
